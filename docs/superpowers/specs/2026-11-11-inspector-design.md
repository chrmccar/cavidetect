# Design — cavidetect Inspector (spatial + temporal review overlay)

**Date:** 2026-11-11
**Status:** approved by Chris ("do it", best-judgment); Phase 1 building now.

## Context — why

The detector now produces good embolised-area results, but there is no way to *inspect
a sequence*: to see **where** embolism sits in the tissue, **which conduit is which**, and
**when** each filled — and to correct the machine's guess when it is wrong. Chris asked for an
overlay like the OSOV / cavicam optical-vulnerability video (Vimeo 215769356; three stills saved
at project root `11nov-1/2/3.png`): stacked panels of raw tissue, a frame-difference image, and
the embolised conduits coloured on black. He wants conduits separable by colour (to tell rhizoids
apart), a temporal dimension, and the ability for the computer and user to trace/correct the
suggested rhizoids and re-run until satisfactory. It must feel like one polished part of the
existing cavidetect app (same place as the GUI), for an official tone.

Decisions (Chris, via AskUserQuestion 2026-11-11): colour encodes **both** time and tube identity
as toggle modes; corrections are **view by default, commit on demand**; the editing surface is a
**full toolkit** (add/erase/split/merge/relabel); integration is **launched from the cavidetect
GUI**, not a separate app. Delivery is **phased**.

## What it is

A first-class review view, generated by `run()` as `<stem>_cs_inspect.html` and opened from a new
**🔍 Inspect** button in the GUI. It is an output/review layer over *any* detection method's
result — orthogonal to `methods.py`. It never alters the auto result; corrections (Phase 2)
produce a separate corrected run.

## Phase 1 — view-only inspector (this build)

**Layout — three vertically-stacked, synchronised panels** (OSOV faithful):
- **raw** greyscale tissue;
- **difference** image (change between consecutive shown frames, symmetric grey, 128 = no change);
- **conduits** on black, coloured by the active mode.
All three share one time **scrubber + ▶ play** and one pan/zoom (a wrapping `#stage` transform).

**Colour modes (toggle on the conduits panel):**
- **by time** — each conduit coloured by its onset frame via a perceptual (blue→red) ramp
  (OSOV look). Source: `result["onset"]`.
- **by tube** — each rhizoid a distinct hue (golden-ratio HSL) so they separate spatially.
  Source: a per-rhizoid label map from `inspector.label_tubes(result["shape"])`.
Both modes **reveal over time** (a pixel appears at its onset frame as you scrub/play); a
**static** toggle shows the all-time summary ignoring the playhead.

**How it is built (reuses existing patterns):**
- Raw + difference panels: pre-rendered at ~90 sampled timepoints, one frame normalised at a
  time to uint8 (the `outputs._grey_u8` memory-safe pattern), embedded as base64 JPEG.
- Onset map and tube-id map: downscaled **NEAREST** to the panel size and encoded **losslessly**
  as RGBA PNG (value = R + 256·G, alpha = valid), embedded base64. JS decodes once and colours
  the conduits canvas live — so mode/static toggles and animation are instant and no colouring
  is baked server-side.
- HTML/CSS/JS mirrors `_VIEWER_HTML`; opened via the GUI's existing `webbrowser.open`.

**Code:**
- New `cavidetect/inspector.py`: `label_tubes()`, `_encode_u16_png()`, `prepare_inspector_frames()`,
  `save_inspector()`, `_INSPECTOR_HTML`.
- `colour_shape.run()`: one `inspector.save_inspector(stack, r, out_dir, f"{stem}_cs")` call
  beside `save_embolism_viewer`.
- `gui.py`: `artefact_paths` gains `"inspect"`; a 🔍 Inspect button + `_open_inspector`; enabled
  when the file exists; included in the bundle.

**Tests (VM, headless):** `tests/test_inspector.py` — `label_tubes` (line→1 label, crossing→split,
empty→zeros, tiny→connected-component fallback, every True pixel labelled), PNG value round-trip,
`save_inspector` writes a file containing both mode markers + embedded JPEG + PNG maps and does not
crash on an all-empty mask, frame count == sampled timepoints. The live canvas is a Mac-browser
check (VM has no display), per project norm.

## Phase 2 — correction loop (next revision round)

Full editing toolkit on the conduits canvas (add-trace → snap to ridge → onset read from the stack
via `onset_start_of_rise`; erase; split at a junction; merge; relabel). Edits are visual until a
**Commit** button exports an edits JSON (the `save_multiframe_annotator` stroke/orig-coords pattern)
that a new `cavidetect inspect-apply` path consumes to recompute the onset / area-curve / per-tube
tables, regenerate the inspector, and reopen it — with the area curve + per-tube table updating
live as the objective feedback. The auto run is preserved; the corrected run saves alongside.

## Out of scope / deferred
- "difference vs dry final" toggle (Phase 1 ships consecutive-frame difference only; revisit on
  collaborator feedback — see the end-user question list).
- Linking frames → timestamps → water potential (unchanged; onset stays in frame units).
